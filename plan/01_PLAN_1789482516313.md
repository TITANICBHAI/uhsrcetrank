# UHSR CET Rank Calculator 2026 — Build Plan
> Part of a 5-file specification. Read `00_MASTER.md` before this file. Architecture details in `02_ARCHITECTURE.md`. Prompts in `03_PROMPTS.md`. Track progress in `04_TRACKER.md`.

## Project Goal

Ship a polished, fully functional "Data Not Available" website before UHSR CET 2026 results publish (expected within 2–4 weeks of the September 13 exam). When results drop, the admin imports the data in one session and the calculator goes live — zero redesign, zero code changes.

**Test sequence for done criteria:**
1. Start backend locally
2. Import a small test dataset directly via Python (or curl):
   ```bash
   curl -X POST http://localhost:8000/admin/datasets/import \
     -H "X-Admin-Secret: your-secret" \
     -F "cet_exam=bsc-nursing" \
     -F "markdown_file=@test_data/small_sample.md"
   ```
3. Check validation report: `GET /admin/datasets/{id}/validation`
4. Publish: `POST /admin/datasets/{id}/publish`

7. Enter a roll number from the test dataset → redirects to `result.html`
8. `result.html` shows candidate details + merit position + "candidates ahead"
9. Enter a non-existent roll number → inline error, no `alert()`
10. Unpublish the dataset → search returns "unavailable" state
11. Nearby candidates and paginated candidates-above rows load without exposing other candidates' DOB/category

## Phase 4 — Admin Panel

**Goal:** A safe dataset lifecycle. Heavy parsing stays local; D1 receives only validated, locally exported data. The protected Worker handles review and publish actions.

**Prompt:** Prompt 6 (Admin Panel)

**Inputs:** Phase 3 fully complete.

**What changes in this phase:**
- `frontend/admin.html` / `frontend/js/admin.js` — review and protected lifecycle UI where deployed
- `app/routers/admin.py` — local compatibility importer and lifecycle implementation
- `backend/export_d1.py` — production D1 SQL/JSON exporter
- `worker/src/index.js` — protected D1 list, validation, publish, unpublish, and delete actions

**Manual test sequence:**
1. Open `admin.html` in browser
2. Enter wrong secret → 401 message appears, secret cleared from sessionStorage
3. Enter correct secret → stored in sessionStorage
4. Process valid Markdown locally with `backend/export_d1.py` → validation report and SQL appear
5. A malformed or unresolved dataset exits without a production SQL import
6. Import reviewed SQL into D1, then inspect the dataset through protected Worker actions
7. Attempt to publish a failed dataset → blocked with validation error
8. Publish a valid dataset → dataset appears in public search
9. Unpublish → public search returns "unavailable"
10. Delete an unpublished dataset → disappears from dataset table
11. Attempt to delete a published dataset → blocked

**Done criteria:**
- [ ] Admin login (secret) stores in sessionStorage, not sent until needed
- [ ] 401 on wrong secret clears stored secret and shows error
- [ ] Local exporter produces ImportReport JSON summary (total rows, successful, failed, warnings count)
- [ ] Validation report renders inline (not in a separate page)
- [ ] "Publish" button disabled for datasets with `is_passed = False`
- [ ] "Delete" button disabled for published datasets
- [ ] Publishing one dataset for a CET exam automatically unpublishes the previous one
- [ ] All admin API calls include `X-Admin-Secret` header
- [ ] `Cache-Control: no-store` on all `/admin/*` API responses

## Decision Points

### Decision Point 1 — Ranking Algorithm Verification
Triggered when: UHSR publishes the 2026 result.

Steps:
1. Import full dataset for each CET exam via admin panel
2. Note UHSR's ordering from the published document (or extract it)
3. Call `RankingVerifier.compare_against_published(our_ranking, uhsr_published_order)` where `uhsr_published_order` is a list of roll numbers in UHSR's sequence
4. If `agreement_percentage < 100.0`, examine `disagreements` — find the criterion that explains them
5. Update `PLACEHOLDER_CONFIG.criteria` in `ranking_config.py` — try reordering criteria (e.g., swap `DOB_ASC` ↔ `DOB_DESC`, add new criterion)
6. Re-run verifier until `agreement_percentage == 100.0`
7. Update `PLACEHOLDER_CONFIG.version` to `"v1-verified-2026"`
8. Re-publish datasets — `ranking_disclaimer` disappears automatically from all result pages
9. No frontend changes needed

### Decision Point 2 — PDF Source Format
If UHSR publishes only a scanned PDF (not a text PDF):
- Use an OCR tool first (Google Docs import trick, or `pytesseract`)
- Then export as Markdown, feed to the importer as normal
- The importer handles messy output regardless of source

If UHSR publishes a text-layer PDF:
```bash
python -c "
import pdfplumber, sys
with pdfplumber.open(sys.argv[1]) as pdf:
    for page in pdf.pages:
        text = page.extract_text()
        if text:
            print(text)
" uhsr_result_2026.pdf > uhsr_result_2026.md
```

### Decision Point 3 — Additional CET Exams
If UHSR publishes 2026 data for CET exams not in the current catalogue, add them to:
- `KNOWN_EXAMS` list in `app/routers/public.py`
- `CONFIG.cetExams` array in `frontend/js/config.js`
- CET catalogue table in `00_MASTER.md`
- CET selector in `admin.html`

No other changes needed.

### Decision Point 4 — Local database to D1
SQLite is used only for the local compatibility app and importer smoke tests. Production uses D1:
1. Create a D1 database and put its ID in `worker/wrangler.toml`.
2. Apply `worker/schema.sql`.
3. Generate a reviewed SQL file with `backend/export_d1.py`.
4. Import with Wrangler and publish through protected Worker actions.
5. Never expose D1 credentials to the browser. Re-import a corrected version rather than mutating published candidate rows in place.

## What NOT to Build (Scope Boundaries)

These are explicitly out of scope. Do not implement them, suggest them, or stub them in.

| Feature | Why excluded |
|---------|-------------|
| College prediction | Fundamentally different product; requires counselling data |
| Seat allocation simulation | Requires preference data, round data — not part of CET result |
| Admission chances / cutoffs | Out of scope; misleading without complete allocation data |
| Historical calculators (2022–2025) | This is a 2026-only product |
| "Your rank is good/bad" judgements | Numbers speak for themselves |
| Show other candidates' full personal info | Privacy; minimize exposure of third-party personal data |
| Countdown to results | No fake urgency; just show "not available yet" cleanly |
| Comparison with other candidates | Out of scope |
