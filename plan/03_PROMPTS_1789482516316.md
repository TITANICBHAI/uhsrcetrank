## Prompt 3 — Implement the Markdown importer and validation

### Objective

Turn messy PDF-converted Markdown into auditable candidate records without guessing.

### Instructions

Implement:

- `table_extractor.py`
- `candidate_normalizer.py`
- `validation_engine.py`
- `markdown_importer.py`
- realistic fixtures and importer tests

Support repeated headers, separator rows, page artifacts, common date formats, percentage signs, null-like values, whitespace corruption, duplicate roll numbers, and modest column shifts.

Every successful candidate must retain source row information. Every failed row must produce a structured reason. Preserve unknown columns in `extra_fields_json`.

Do not implement an arbitrary universal minimum of 100 candidates. Use the validation policy in `02_ARCHITECTURE.md`: fail when the dataset is materially unusable, not merely small.

Duplicate handling must distinguish:

- exact duplicate row that can be safely deduplicated and warned;
- conflicting records with the same roll number, which block publication until resolved.

### Verification

Write tests for:

- repeated headers;
- multiline row repair;
- date formats;
- percent signs;
- null-like values;
- duplicate and conflicting duplicate records;
- unknown columns;
- malformed rows;
- a small fixture with exact expected output.

Run:

```bash
pytest -q tests/test_importer.py
```

Do not use real candidate data in committed fixtures.

## Prompt 8 — Activate a real dataset after publication

### Objective

Activate results only after provenance, parsing, ranking, and public smoke tests pass.

### Instructions

Follow `05_DATA_ACTIVATION_RUNBOOK.md` exactly. Do not make code changes to force a result.

For each CET exam:

1. Archive the original official source privately.
2. Record URL, retrieval date, checksum, and conversion method.
3. Import into a new unpublished dataset version.
4. Review all validation warnings and conflicts.
5. Compare published order, if present.
6. Verify or explicitly document the ranking method.
7. Run a manual sample of known roll numbers.
8. Publish only after the operator signs off.
9. Test rollback by keeping the prior version available.

If the evidence is incomplete, leave the calculator unavailable for that exam and explain why. Do not fill gaps with assumptions.
